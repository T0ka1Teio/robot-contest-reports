# 机器人漏洞报告

本仓库用于团队协作提交**已经挖掘、实际验证并可复现的漏洞报告**，仅存放报告，不存放工具、扫描输出或原始证据包。

## 提交位置

| 目录 | 对应环境 |
|---|---|
| [`env1/`](./env1/) | 人形机器人1验证环境 |
| [`env2/`](./env2/) | 人形机器人2验证环境 |

请将报告放入对应环境目录，不要提交到仓库根目录。即使两个环境出现相似问题，也应分别注明目标版本、验证结果与环境，避免混淆。

## 收录要求

- 漏洞已实际验证，具有明确的安全边界突破及影响证据。
- 提供可复现步骤、必要前置条件、正常行为与实际结果，以及修复建议。
- 明确区分已验证影响与推断；候选假设、未确认发现、轮次记录和仅有版本指纹的结果不作为漏洞报告提交。
- 每个独立根因一份报告；提交前检查已有报告，避免重复。
- 本仓库公开可见，仅提交符合赛事公开要求且已完成审核、脱敏的报告版本。不得包含密码、令牌、私钥、个人信息或不应公开的内部数据。

## 报告格式

推荐使用 Markdown，命名为 `YYYY-MM-DD-漏洞简短名称.md`。

报告至少包含：

1. 标题、对应环境、设备/组件及版本、验证时间。
2. 漏洞摘要、访问前提及所需权限。
3. 正常行为、最小复现步骤及实际结果。
4. 经脱敏的关键证据、重复复现结果及影响范围。
5. 根因分析（推断须标注）、修复建议。
6. 涉及状态修改时的清理与恢复结果。

原始抓包、完整日志、点云/业务数据、凭据及测试脚本不上传本仓库；在报告中保留必要的脱敏片段与证据摘要即可。

## 提交流程

1. 在对应目录新增或更新报告。
2. 提交 Pull Request，说明环境、漏洞标题和验证状态；建议由另一位成员复核后合并。
3. 若使用直接写入权限，提交前同样完成复现、脱敏与公开审核。

**GitHub 留档不替代比赛平台正式提交。** 需要参赛计分的报告仍按赛事要求在比赛平台提交，并在本地保存提交回执。
